# Сценарий скринкаста Kubernetes

Рекомендуемая продолжительность: 5–7 минут.

## Подготовка до начала записи

Убедиться, что Docker Desktop и Minikube работают:

```bash
minikube status
kubectl get nodes
```

Проверить наличие образов в Minikube:

```bash
minikube image ls | grep climate-store
```

Должны присутствовать:

```text
docker.io/library/climate-store-backend:1.0
docker.io/library/climate-store-frontend:1.0
```

Закрыть лишние приложения и увеличить шрифт терминала. Заранее открыть каталог проекта и браузер.

Для чистой демонстрации перед началом записи удалить Namespace:

```bash
kubectl delete namespace climate-store --ignore-not-found
kubectl wait --for=delete namespace/climate-store --timeout=120s
```

Эта операция удаляет ресурсы и данные приложения только внутри Minikube. После повторного развёртывания миграции и seed восстановят каталог.

## 1. Введение — около 30 секунд

Кратко сказать:

> Я разворачиваю клиент-серверное приложение Climate Store в однодовом Kubernetes-кластере Minikube. Приложение состоит из React frontend, Express backend и PostgreSQL. Для frontend и backend подготовлены отдельные Docker-образы.

Показать работающий кластер:

```bash
kubectl get nodes
```

## 2. Запуск конфигурации и PostgreSQL — около 1 минуты

Создать Namespace, Secret и ConfigMap:

```bash
kubectl apply -f k8s/00-namespace.yaml
kubectl apply -f k8s/01-secret.yaml
kubectl apply -f k8s/02-configmap.yaml
```

Запустить PostgreSQL:

```bash
kubectl apply -f k8s/03-postgres.yaml
kubectl wait --for=condition=ready pod/postgres-0 -n climate-store --timeout=180s
```

Кратко сказать:

> PostgreSQL запущен через StatefulSet. Данные сохраняются в PersistentVolumeClaim, а доступ внутри кластера предоставляется Service с именем postgres.

Показать ресурсы:

```bash
kubectl get statefulset,service,pvc -n climate-store
```

## 3. Миграции и seed — около 40 секунд

Создать одноразовый Job:

```bash
kubectl apply -f k8s/04-migration-job.yaml
kubectl wait --for=condition=complete job/climate-store-db-init -n climate-store --timeout=120s
kubectl logs job/climate-store-db-init -n climate-store
```

Кратко сказать:

> Job применяет миграции Drizzle и добавляет демонстрационные данные, после чего успешно завершается.

## 4. Запуск backend и frontend — около 1 минуты

Применить манифесты:

```bash
kubectl apply -f k8s/05-backend.yaml
kubectl apply -f k8s/06-frontend.yaml
```

Дождаться готовности:

```bash
kubectl rollout status deployment/backend -n climate-store
kubectl rollout status deployment/frontend -n climate-store
```

Показать все Pod:

```bash
kubectl get pods -n climate-store
```

Ожидаемый результат:

- `postgres-0` — `Running`, `1/1`;
- backend — `Running`, `1/1`;
- frontend — `Running`, `1/1`;
- Pod Job — `Completed`.

Кратко сказать:

> Frontend и backend запущены через Deployment. Внутренние Service имеют тип ClusterIP, а frontend опубликован через NodePort. Readiness-пробы не допускают трафик к неготовым Pod, а liveness-пробы позволяют Kubernetes перезапускать неисправные контейнеры.

## 5. Открытие UI — около 1–2 минут

В отдельном терминале получить адрес frontend:

```bash
minikube service frontend -n climate-store --url
```

Терминал с этой командой необходимо оставить открытым. Скопировать выведенный URL в браузер.

В UI показать несколько действий:

1. открыть каталог;
2. воспользоваться поиском или фильтром;
3. открыть карточку кондиционера;
4. перейти в административный раздел;
5. изменить тестовый товар или добавить новый.

Кратко объяснить взаимодействие:

> Браузер обращается к frontend. Nginx раздаёт React-приложение и перенаправляет запросы `/api` на Service backend. Backend через Service postgres подключается к PostgreSQL. Имена backend и postgres разрешаются внутренним DNS Kubernetes.

## 6. Масштабирование — около 1 минуты

В терминале показать исходное количество реплик:

```bash
kubectl get deployments,pods -n climate-store
```

Увеличить число реплик:

```bash
kubectl scale deployment/backend --replicas=3 -n climate-store
kubectl scale deployment/frontend --replicas=3 -n climate-store
```

Дождаться готовности:

```bash
kubectl rollout status deployment/backend -n climate-store
kubectl rollout status deployment/frontend -n climate-store
kubectl get deployments,pods -n climate-store
```

Кратко сказать:

> Kubernetes создал по три Pod frontend и backend. Service автоматически распределяют запросы между готовыми репликами. PostgreSQL не масштабируется этой командой, поскольку для базы данных требуется специальная настройка репликации.

Обновить страницу приложения и показать, что UI продолжает работать после масштабирования.

## 7. Завершение — около 20 секунд

Кратко подвести итог:

> В Minikube запущены frontend, backend и PostgreSQL. Для конфигурации используются ConfigMap и Secret, для хранения данных — PVC, для инициализации базы — Job. Stateless-сервисы успешно масштабируются с одной до трёх реплик.

После записи при необходимости вернуть исходное число реплик:

```bash
kubectl scale deployment/backend --replicas=1 -n climate-store
kubectl scale deployment/frontend --replicas=1 -n climate-store
```

## Если во время записи возникла проблема

Общая проверка:

```bash
kubectl get all,pvc -n climate-store
```

Логи backend:

```bash
kubectl logs deployment/backend -n climate-store --tail=50
```

Логи frontend:

```bash
kubectl logs deployment/frontend -n climate-store --tail=50
```

Логи PostgreSQL:

```bash
kubectl logs postgres-0 -n climate-store --tail=50
```

Если перестал открываться временный URL, повторно запустить:

```bash
minikube service frontend -n climate-store --url
```
